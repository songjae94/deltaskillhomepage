## 2. ★ 방향 전환 (08-12) — 데모와 실화면을 갈랐다

v2까지는 "`/pilot2/live/` 데모에 백엔드를 붙여 실데이터로 바꾼다"는 그림이었다. **바꿨다.**

| | 경로 | 데이터 | 용도 |
|---|---|---|---|
| **데모** | `/pilot2/live` `self` `academy` | **가상 유지** | 영업·소개. 1,000명·5개 분원 같은 큰 그림을 보여줘야 하는데 실데이터는 202명뿐이라 **줄이면 오히려 설득력이 준다** |
| **실화면** | **`/admin/`** | **실데이터** | 운영자가 실제로 쓰는 화면. `admin-api`로 Supabase 직결 |

**이유**: 데모는 "규모의 상상"을 팔고, 실화면은 "이번 주 누구를 잡을지"를 판다. 요구가 달라서 한 화면으로 겸하면 둘 다 어정쩡해진다. 운영자가 "데모용 자료가 꼭 실측 데이터일 필요는 없다"고 확인해 준 지점.

**대신 데모는 실화면에서 검증된 것만 보여준다** — `/admin/` 반별 현황에서 실제로 돌아간 집계·급락 탐지·추이가 데모의 근거다. 데모에만 있는 기능을 새로 상상해 넣지 않는다.

## 4. ★ 기관 백엔드 — "미착수"가 아니었다 (08-12 코드 확인)

v2 문서 §3의 "C단계 미착수"는 **틀린 서술이었다.** `admin-api`를 직접 열어 보니 절반이 이미 있었다.

### 4-1. v4에 이미 있던 것
| 요소 | 내용 |
|---|---|
| `admins(role, academy)` | 관리자 계정. 현재 **1개, `role='owner'`**(운영자 본인) |
| `admin_sessions` | 토큰 해시 · 12시간 만료 |
| `admin_login` · `rl_hit` RPC | 로그인 + 레이트리밋 |
| **서버측 학원 범위 강제** | `role='academy'`면 `students.academy` 밖을 못 본다 — 프론트가 아니라 서버가 막는다 |
| 액션 | `login` `logout` `students` `student` |

즉 §7의 "기관 계정 체계"는 **설계 쟁점이 아니라 이미 선 구조**다. 남은 건 계정을 늘리고 학원별로 배정하는 운영 문제.

### 4-2. v5에서 추가한 것 (08-12 배포, 둘 다 `role='owner'` 전용 · 403 차단)
- **`cohort`** `{exam_code?, prev_exam_code?, classes?[]}` → 회차·반 목록, 반별 집계(인원·평균·SD·평균등급·선택과목 분포), 반×회차 추이, 알림(직전 회차 대비 **−10점 이상 급락** / 미응시). 회차 생략 시 최신.
- **`items`** `{exam_code, subject?}` → 문항별 정답률·정답·선택지 분포. **단답형은 `objective:false`** 로 오답 분포를 만들지 않는다(c1~c5가 전부 0이라 만들면 거짓이 된다). 객관식은 `top_wrong`.
- **기하 제외**: 상수 `EXCLUDED_TRACKS`로 두 액션 모두에서 거른다. `subject:"기하"` 직접 요청은 `excluded_track`(400).
- 롤백은 v4 재배포. 기존 액션 미변경.

### 4-3. 실데이터 규모 (`official_scores`)
- **운영자가 강사로서 보유한 한 학원의 성적 명단.** 623행(OMEGA_5·6·7·8) + JEONDAE_7 218행. **202명.**
- 컬럼: `class`(I1~I11 · 일산 01~11반), `math_type`, `korean`/`english`/`math`, `math_grade_est`, `student_no`(학번, 08-12 추가·백필 완료).
- 적재 규칙 **수학 응시자만** — 원본 248/245/244/241명 → DB 184/147/137/155행으로 정확히 일치.
- 조인 키는 **`student_no`**(이름 아님).
- ⚠️ **`role='owner'` 전용으로 다룰 것.** 학원 계정에 열면 동의 범위 밖 개인정보 제공이 된다.
- 문항 통계는 `item_stats` — OMEGA_5~8 확통·미적분만 238행.

### 4-4. `/admin/` 반별 현황 화면 (08-12 완성) = live 데모의 실데이터판 첫 조각
`show()` 로 세 화면 전환: `main`(학생 목록) · `detail`(개인 상담 리포트) · **`cohort`(반별 현황)**.
- 회차 선택 · 반 토글 · KPI · 반별 비교 · **회차 추이(인라인 SVG)** · **이번 주 할 일**(급락/미응시) · 결정 문항.
- `PILOT_CLASSES = ["I1","I2","I5"]` 기본 선택 — **파일럿 범위를 넓히려면 이 상수만 고친다.**
- 첫 대상 3개 반 = **87명**, 성적 스펙트럼 80.5 / 72.6 / 48.7, **I5에 급락 알림이 실제로 켜졌다.**
- 구현 관례(어긴 적 있어 적어 둠): 반 이름에 괄호가 들어가므로(`I11(반수반)`) 토글은 **인덱스 기반**. 반별 표와 "최고–최저 격차"는 **서버 정렬에 기대지 않고 화면에서 다시 정렬·계산**한다.

## 6. 실구동 설계안 — PDF 업로드 자동 완성 파이프라인 (설계 완료 · 미착수)

- **아티팩트**: https://claude.ai/code/artifact/150a9fb9-b5c7-4f1c-b274-9e6af76ba481 (v1 · 2026-08-11)

### 6-1. 결론 3문답
1. **OCR 불필요** — Claude API가 PDF(스캔본 포함, 요청당 32MB·600페이지)를 직접 읽어 수식·한글·그림 처리. "PDF→분석" 1단계.
2. **비용·시간** — 1회분(30~46문항) 분석 **$1~2**, 자동 초안 ~10분 + 검수 10~20분 = **업로드 당일 등재**(현 수작업 1~2일). Batch API로 절반.
3. **완전 무인 아님 — 자동 초안 + 사람 승인**. **정답은 AI가 풀지 않고 반드시 답안표에서 추출.**

### 6-2. 실구동 4블록 현황 (v2 대비 갱신)
| 블록 | v2 상태 | **현재** |
|---|---|---|
| ① 학생 앱 | 완성·배포 | 동일 (`/submit-update` 오류도 해결됨) |
| ② 관리자 화면 | 데모 완성 | **데모 + 실화면(`/admin/` cohort) 완성** |
| ③ 기관 백엔드 | 명세 완료·미착수 | **v5 배포·가동 중** (§4) |
| ④ 자료 파이프라인 | 설계 완료 | 설계 완료 · **미착수** ← 지금 유일하게 안 굴러가는 블록 |

### 6-3. 파이프라인 5단계
1. **업로드**(강사 1분): 문제지 PDF + **답안표(필수)** + 해설지(선택) → Storage, `materials` 「접수됨」.
2. **1차 분석 — 문항 메타**(자동 ~2분, 1회 호출): 문항번호·배점·유형·정답(답안표에서만)·영역·단원·주제를 JSON 스키마 강제 추출. 검증 게이트: 배점 합=100, 문항 수, 정답 형식, 답안표 대조.
3. **2차 분석 — steps·uses·anchors**(자동 ~8분): 5~8문항 묶음 병렬 호출, **기존 등재 문항을 few-shot으로** 제공해 표기·스킬 명명 일치. `material_items` 「검수 대기」.
4. **검수**(사람 10~20분): admin 검수 탭 — 통과 문항 접힘, 플래그 문항만 펼침.
5. **등재**(자동): skills.json 규격 + EXAMS 메타 생성. 기관 전용 시험은 `org/{id}/exams.json`으로 분리.

### 6-4. ★ 착지점이 생겼다 — 원장(ledger) DB (08-12 이관 완료)
파이프라인이 뱉을 산출물이 어디로 가는지가 이제 정해져 있다.

| 테이블 | 행 | 내용 |
|---|---|---|
| `tool_codes` | 55 | 정규 도구코드 — 원장이 참조하는 유일한 어휘 |
| `code_aliases` | 164 | 원시코드 → 정규코드 치환표 |
| `exams` | 101 | 회차 마스터 |
| `ledger_items` | 314 | **진단용** — 문항별 델타 좌표·관문·진단질의 |
| `exam_items` | 152 | **채점용** — 대성 4회차 |

- **DB가 두 사고를 구조적으로 막는다**: `ans_format` CHECK(객관식 답을 아라비아 숫자로 넣으면 거부) · `tool_code` FK(정규 어휘 밖 코드 거부). 파이프라인 산출물도 이 관문을 통과해야 한다 = **검수 게이트의 일부를 DB가 대신 진다.**
- 즉 §6-3 4단계 "검수"의 형식 검증은 이미 DB가 하고 있고, 사람은 **내용**만 보면 된다.

### 6-5. 기술 선택 · 비용
모델 `claude-opus-5` · 1차 1회 + 2차 묶음 호출 · 야간 Batch API(옵션, 50% 절감) · 키는 Supabase Secret `ANTHROPIC_API_KEY`.
1회분 $1~2 / 월(5기관×4주) $20~40. **인강 1,000명: 주간 시험 1회 $2 = 학생당 0.3원** — **병목은 검수 인력**이지 비용이 아니다.

### 6-6. 운영자 결정 대기 3가지 (미결)
| 결정 | 추천 |
|---|---|
| 시작 단계 | **Phase 0 즉시 + Phase 1 병행** |
| 답안표 정책 | **필수** (정답 오류는 신뢰 직결) |
| 등재 SLA | **"영업일 1일 이내"**로 시작 |

## 8. 토론해볼 만한 쟁점

- **데모를 어디까지 실화면에 맞출까** — `/admin/` cohort에서 검증된 기능만 데모에 남길지, 데모는 이상형을 계속 보여줄지.
- 기관별 `org/{id}/exams.json` 분리 vs 단일 skills.json 병합 — 로딩·캐시·권한 트레이드오프.
- 검수 게이트 축소 시점·기준 — DB CHECK가 형식을 막아 주는 지금, 사람 게이트를 언제 얇게 할지.
- 인강(①) 1,000명 온보딩 — 전화번호+PIN 가입을 기관 일괄 처리 vs 개별 가입.
- 학원 계정(`role='academy'`) 실제 발급 — 구조는 있고 계정이 1개(owner)뿐이다. 첫 학원을 언제 태울지.
- 가격 정책 — 파이프라인 원가(학생당 0.3원)와 검수 인건비 기준의 기관 과금 설계.
- 틀린 문항 다시보기(§7-5)와 파이프라인(§6)의 통합 — PDF 한 번 업로드로 "분석 + 문항 이미지"를 동시에 뽑을지.
