## 1. 파일럿2란 — 요구와 경위

운영자 요구(원문 취지):

1. 특정 학원·강사가 사용할 페이지 = **교육기관 도입용 파일럿2**. 우선 **화면 설계안 + 데모**, 실명 대신 가상명.
2. 파일럿을 **3종으로 분화**:
   - **① 유명 인강·대형 단과 강사**: 약 1,000명을 200명 × 5개 지역 학원에서 같은 수업·같은 주간 시험 → 자동 집계·관리.

   - **③ 일반 수학학원**: 반·학년·선생님·진도 제각각 → **원장이 전체를 한 화면에서**.
3. "파일럿을 **실제로 구동**하기 위한 방법, 특히 **자료 PDF 업로드 시 자동 완성**" → 실구동 설계안 작성 완료(§4).
4. (08-11 추가) "**단과 강사용 페이지의 완성도**를 높이고, **기관용(파트너스) 페이지에 홍보**도. 정리된 학생 데이터·리포트·관리 편의성 부각" → 완료(§2-2, §3).

핵심 설계 원칙: **학생 쪽 앱은 3종 모두 기존 `/pilot/`을 그대로 재사용** — 파일럿2는 그 위에 얹는 **관리자(강사·담임·원장) 화면**이다.

## 4. 실구동 설계안 — PDF 업로드 자동 완성 파이프라인 (설계 완료)

- **아티팩트**: https://claude.ai/code/artifact/150a9fb9-b5c7-4f1c-b274-9e6af76ba481 (v1 · 2026-08-11)

### 4-1. 결론 3문답
1. **OCR 불필요** — Claude API가 PDF(스캔본 포함, 요청당 32MB·600페이지)를 직접 읽어 수식·한글·그림 처리. "PDF→분석" 1단계.
2. **비용·시간** — 1회분(30~46문항) 분석 **$1~2**, 자동 초안 ~10분 + 검수 10~20분 = **업로드 당일 등재**(현 수작업 1~2일). 배치 시 비용 절반.
3. **완전 무인 아님 — 자동 초안 + 사람 승인**. **정답은 AI가 풀지 않고 반드시 답안표에서 추출.** 신뢰가 쌓이면 게이트를 점진적으로 얇게.

### 4-2. 실구동 4블록 현황
| 블록 | 상태 |
|---|---|
| ① 학생 앱 | **완성·배포** (현 파일럿 재사용) |
| ② 관리자 화면 | **데모 완성** (백엔드 붙으면 데이터만 교체) |
| ③ 기관 백엔드 | **명세 완료** (테이블 3 + API 7 — Supabase 추가 필요) |
| ④ 자료 파이프라인 | **설계 완료** (PDF→자동 분석→검수→등재) |

### 4-3. 파이프라인 5단계
1. **업로드**(강사 1분): S4 화면에서 문제지 PDF + **답안표(필수)** + 해설지(선택) → Storage, `materials` 「접수됨」.
2. **1차 분석 — 문항 메타**(자동 ~2분, 1회 호출): 문항번호·배점·유형·정답(답안표에서만)·영역·단원·주제를 JSON 스키마 강제 추출. 검증 게이트: 배점 합=100, 문항 수, 정답 형식, 답안표 대조.
3. **2차 분석 — steps·uses·anchors**(자동 ~8분): 5~8문항 묶음 병렬 호출, **기존 등재 문항을 few-shot으로** 제공해 표기·스킬 명명 일치("스타일 복제"). `material_items` 「검수 대기」.
4. **검수**(사람 10~20분): admin 검수 탭 — 통과 문항 접힘, 플래그 문항만 펼침 → 수정·승인.
5. **등재**(자동): skills.json 규격 + EXAMS 메타 생성. **기관 전용 시험은 기관별 JSON**(`org/{id}/exams.json`)으로 분리.

### 4-4. 품질 3장치
① 정답 출처 분리(답안표 없으면 접수 반려, 없는 문항은 `null`) ② 기존 데이터 few-shot ③ JSON 스키마 강제(구조화 출력).

### 4-5. 기술 선택
모델 `claude-opus-5`(품질=상품) · 1차 1회 + 2차 묶음 호출(Edge Function 시간 제한 내 묶음별 저장·재개) · 야간 Batch API(옵션, 50% 절감) · 키는 Supabase Secret `ANTHROPIC_API_KEY`.

### 4-6. 비용·손익
1회분 $1~2 / 월(5기관×4주) $20~40. **인강 1,000명: 주간 시험 1회 $2 = 학생당 0.3원** — 파이프라인 비용은 무시 가능, **병목은 검수 인력** → 검수 UI 효율이 곧 확장성.

### 4-7. 로드맵
- **Phase 0(지금 바로)**: 반자동 — PDF를 Cowork 세션에 넣고 프롬프트·스키마로 초안 → 검수 → 등재.
- **Phase 1(자동 초안)**: Edge Function `analyze-material` + Storage + `materials`/`material_items` + admin 검수 탭. 코드 일체는 Claude 제공, 운영자는 배포만. 선행 조건: **Anthropic API 키 → Supabase Secret 등록**.
- **Phase 2(스케일)**: 야간 배치 · 2회 교차 대조 · 통과율 기반 자동 등재 · 기관별 JSON 자동 배포.

### 4-8. 운영자 결정 대기 3가지
| 결정 | 추천 |
|---|---|
| 시작 단계 | **Phase 0 즉시 + Phase 1 병행** |
| 답안표 정책 | **필수** (정답 오류는 신뢰 직결) |
| 등재 SLA | **"영업일 1일 이내"**로 시작, 안정 후 상향 |

## 6. 토론해볼 만한 쟁점 (제안)

- 기관별 `org/{id}/exams.json` 분리 vs 단일 skills.json 병합 — 로딩·캐시·권한 트레이드오프.
- 검수 게이트 축소 시점·기준 — 자동 등재 신뢰 구간을 무엇으로 정의할지.
